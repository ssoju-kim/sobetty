3D 생성 AI 학습 데이터 검증과 모델 평가 — 상세

개요

스팩스페이스 개발사업부 CV팀 소속으로 2026년 1월부터 7월까지(1~2월 · 7월 프리랜서, 3~6월 IPP 장기현장실습) 한국 문화 특화 3D 에셋 생성 정부지원 R&D 과제에 참여했습니다.

문제와 목표

학습 데이터 품질과 평가 조건이 정리되어 있지 않아 결과를 신뢰하거나 재현하기 어려운 상태였습니다. 데이터를 점검해 사용 가능한 범위를 확정하고, 평가 조건의 근거를 구분하는 것이 과제였습니다.

내가 맡은 역할

  • 3D 학습 데이터 1,500건 점검과 사용 가능 데이터 분류
  • TRELLIS2 기반 LoRA 학습 실행과 체크포인트별 결과 비교
  • 정량평가 지표 조사와 실행, 평가 코드 · 렌더링 · 입력 조건 검증
  • 평가 조건 근거 리서치와 인수인계 문서화

수행 과정

  1. 3D 학습 데이터 1,500건을 점검해 사용 불가 데이터를 분류하고 1,451건으로 정리
  2. 학습 1,268건 / holdout 143건으로 분할하고, 두 집합 간 데이터 누출 여부와 캡션 · 프롬프트 결측을 점검
  3. 논문 · 공식 코드 · 후속 연구 구현을 대조해 평가 조건별 근거를 4단계로 분류
  4. TRELLIS2 기반 LoRA 학습을 실행하고 체크포인트별 생성 결과를 비교
  5. 정량평가 지표와 실행 조건을 조사해 실행하고, 평가 코드 · 렌더링 · 입력 조건이 의도대로 동작하는지 검증

결과와 한계

  • 과제 목표 성능에는 도달하지 못했습니다. 미달 원인을 데이터 · 전처리 · 평가 조건 · 체크포인트 관점으로 분리해 분석하고, 시도한 개선안과 그 결과를 기록했습니다.
  • 후속 담당자와 시험기관이 같은 조건으로 재현할 수 있도록 데이터 구성, 평가 지표, 실행 환경, 실행 명령어를 실행 문서로 정리했습니다.

정성평가는 실행 전 단계에서 비교 대상, 평가 항목, 평가자 구성을 계획하는 데까지 진행했습니다. 실제 평가는 진행하지 않았습니다.

산출물

  • 확인된 사실과 미확인 사항을 구분해 표기한 인수인계 자료
  • 사업계획서 시장조사 영역 담당 (3D 생성 AI 시장 · 경쟁 서비스 조사)
  • Relic 랜딩페이지 기획부터 구현까지 담당

금융 데이터 통합과 정합성 검증 — 상세

개요

은행 · 카드 · 증권 모의 제공기관 데이터를 통합하고, 통합 결과의 정합성을 검증한 개인 프로젝트입니다. 실제 금융회사 데이터가 아닌 모의 데이터를 사용했습니다. (2026년 6월 – 7월)

문제와 목표

기관마다 형식이 다른 데이터를 하나로 모으면 통합 과정에서 생긴 누락 · 중복 · 금액 오류가 드러나지 않습니다. 통합 결과를 원천과 대사해 오류를 자동으로 찾는 것이 과제였습니다.

내가 맡은 역할

  • 은행 · 카드 · 증권 모의 제공기관 API에서 데이터 수집
  • 기관마다 다른 필드명 · 날짜 · 금액 형식을 공통 스키마로 표준화
  • 원천 → 표준 → 운영 3개 계층으로 데이터 통합, (원천, 원천레코드ID) 키로 중복 병합
  • 누락 · 중복 · 금액 · 건수/잔액 불일치 4개 정합성 검증 규칙 설계 · 구현
  • 대사 결과를 확인하는 웹 대시보드 구현

수행 과정

  1. 은행 · 카드 · 증권 모의 제공기관 API에서 데이터를 수집해 원천 → 표준 → 운영 3개 계층으로 적재
  2. 기관마다 다른 필드명 · 날짜 · 금액 형식을 공통 스키마로 정규화하고, (원천, 원천레코드ID)를 키로 중복 병합
  3. 통합 결과를 원천 · 정답집합과 대사해 누락 · 중복 · 금액 불일치 · 건수/잔액 불일치 4개 규칙으로 검증

결과와 한계

  • 대사 대상 84건 중 의도적으로 삽입한 오류 15건 검출 (누락 12 · 중복 1 · 금액 불일치 1 · 건수 · 잔액 불일치 1)
  • 모든 운영 레코드에 원천 · 원천레코드ID · 원본 링크를 남겨 역추적이 가능하도록 설계
  • 오류 발생 원인을 페이지 타임아웃 · 재전송 · 환율 반올림 등으로 구분해 기록
  • 오류 판정은 규칙 기반으로 처리하고, 생성형 AI는 결과 설명 보조 용도로만 사용했습니다. 판정 자체를 AI에 맡기지 않아 결과를 재현하고 검증할 수 있도록 했습니다.

  • Supabase SQL 스키마 · 마이그레이션 · 감사 로그

MAPLESSUNDAY 이벤트 예측 서비스 — 상세

개요

커뮤니티에서 반복되던 "다음 이벤트는 언제인가"라는 질문을 서비스 문제로 정의하고, 예측 · 캘린더 · 캐릭터 조회 · 공지 조회를 하나의 웹서비스로 묶었습니다. 2인 팀으로 2026년 3월부터 개발해 5월에 출시했습니다.

문제와 목표

2017년 3월부터 2026년 5월까지 이벤트 이력이 공지 · 커뮤니티 · 위키에 흩어져 있어, 다음 이벤트를 예측할 재사용 가능한 데이터가 없는 상태였습니다.

내가 맡은 역할

본인과 팀원의 역할은 아래와 같이 구분됩니다.

본인

  • 백엔드 API 개발 (FastAPI)
  • Supabase 데이터베이스 설계 및 연동
  • 넥슨 오픈 API 등 외부 API 연동
  • Render 배포 및 운영
  • 이벤트 이력 수집 · 구조화

팀원

  • 예측 모델 구현
  • 프론트엔드 구현

수행 과정

  1. 2017년 3월 – 2026년 5월 이벤트 약 455건을 공지 · 커뮤니티 · 위키에서 수집해 날짜 · 이벤트명 · 혜택 · 태그로 구조화
  2. 캐릭터 · 공지 · 예측 API 엔드포인트를 구성하고, 넥슨 오픈 API 응답을 가공해 Supabase와 연동
  3. 외부 호출을 비동기로 처리하고 429 · 5xx · 타임아웃에 지수 백오프 재시도, TTL 캐시(30분 · 1시간)와 GZip 압축, 헬스체크를 적용
  4. API 키와 접속정보를 환경변수로 분리해 Render에 배포하고 운영

결과와 한계

  • 2026년 5월 서비스 출시 — 이벤트 후보 예측, 과거 이벤트 캘린더, 캐릭터 조회, 공지 조회 기능
  • 10주 백테스트 중 9주 TOP3 적중은 팀 백테스트 결과이며, 예측 모델 구현은 팀원이 담당했습니다.
  • 인벤 홍보 게시글 조회수 7.6만 회는 서비스 방문자 수와는 별도의 지표이며, 팀 결과입니다.
