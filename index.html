3D 생성 AI 학습 데이터 검증과 모델 평가

  • 역할

    학습 데이터 점검·구성, LoRA 학습 실행, 정량평가 실행, 평가 조건 리서치와 문서화

  • 핵심 결과

    학습 데이터 1,500건을 점검해 1,451건으로 정리하고, 평가 조건을 근거 4단계로 분류해 재현 가능한 실행 문서로 인계

2026년 1월 – 7월 1~2월 · 7월 프리랜서 / 3~6월 IPP 장기현장실습

  • 1,451건

    정리한 유효 학습 데이터

    원본 1,500건 점검 후

  • 1,268 / 143

    학습 · holdout 분할

    두 집합 간 데이터 누출 여부 점검

  • 4단계

    평가 조건 근거 분류

    논문 명시 · 공식 코드 · 후속 관행 · 미확인

배경

한국 문화 특화 3D 에셋 생성 정부지원 R&D 과제였습니다. 학습 데이터 품질과 평가 조건이 정리되어 있지 않아 결과를 신뢰하거나 재현하기 어려운 상태였습니다.

수행 내용 · 핵심 3

  1. 3D 학습 데이터 1,500건을 점검해 사용 불가 데이터를 분류하고 1,451건으로 정리
  2. 학습 1,268건 / holdout 143건으로 분할하고, 두 집합 간 데이터 누출 여부와 캡션·프롬프트 결측을 점검
  3. 논문·공식 코드·후속 연구 구현을 대조해 평가 조건별 근거를 4단계로 분류

결과

  • 과제 목표 성능에는 도달하지 못했습니다. 미달 원인을 데이터 · 전처리 · 평가 조건 · 체크포인트 관점으로 분리해 분석하고, 시도한 개선안과 그 결과를 기록했습니다.
  • 후속 담당자와 시험기관이 같은 조건으로 재현할 수 있도록 데이터 구성, 평가 지표, 실행 환경, 실행 명령어를 실행 문서로 정리

기술 Python · PyTorch · TRELLIS2 · LoRA · Linux

세부 수행 내용

  1. TRELLIS2 기반 LoRA 학습을 실행하고 체크포인트별 생성 결과를 비교
  2. 정량평가 지표와 실행 조건을 조사해 실행하고, 평가 코드·렌더링·입력 조건이 의도대로 동작하는지 검증

추가 산출물

  • 확인된 사실과 미확인 사항을 구분해 표기한 인수인계 자료
  • 사업계획서 시장조사 영역 담당(3D 생성 AI 시장·경쟁 서비스 조사)
  • Relic 랜딩페이지 기획부터 구현까지 담당

정성평가는 실행 전 단계에서 비교 대상, 평가 항목, 평가자 구성을 계획했습니다. 실제 평가는 진행하지 않았습니다.

  • 핵심 결과

    모의 데이터 84건을 대사해 의도적으로 삽입한 오류 15건을 4개 검증 규칙으로 검출

2026년 6월 – 7월 · 모의 금융 데이터

GitHub 저장소

배경

기관마다 형식이 다른 데이터를 하나로 모으면 통합 과정에서 생긴 누락·중복·금액 오류가 드러나지 않습니다. 통합 결과를 원천과 대사해 오류를 자동으로 찾는 것이 과제였습니다.

수행 내용 · 핵심 3

  1. 은행·카드·증권 모의 제공기관 API에서 데이터를 수집해 원천 → 표준 → 운영 3개 계층으로 적재
  2. 기관마다 다른 필드명·날짜·금액 형식을 공통 스키마로 정규화하고, (원천, 원천레코드ID)를 키로 중복 병합
  3. 통합 결과를 원천·정답집합과 대사해 누락·중복·금액 불일치·건수/잔액 불일치 4개 규칙으로 검증

결과

  • 대사 대상 84건 중 의도적으로 삽입한 오류 15건 검출 (누락 12 · 중복 1 · 금액 불일치 1 · 건수·잔액 불일치 1)
  • 오류 판정은 규칙 기반으로 처리하고, 생성형 AI는 결과 설명 보조 용도로만 사용

기술 Python · SQL · Supabase(PostgreSQL) · Next.js

세부 구현

  • 모든 운영 레코드에 원천·원천레코드ID·원본 링크를 남겨 역추적이 가능하도록 설계
  • 오류 발생 원인을 페이지 타임아웃 · 재전송 · 환율 반올림 등으로 구분해 기록

추가 산출물

  • 대사 결과를 확인하는 웹 대시보드
  • Supabase SQL 스키마 · 마이그레이션 · 감사 로그
